# Производственный профиль

Производственный профиль — это цифровой паспорт производственного предприятия.

Он является центральной сущностью системы и используется для:

- анализа производственных возможностей;
- подбора подходящих заказов;
- формирования рекомендаций;
- подготовки цифрового профиля предприятия.

Производственный профиль заполняется поэтапно.

Для MVP используется минимальный набор обязательных полей. По мере необходимости пользователь может дополнить профиль расширенной информацией.

## Основные принципы

Производственный профиль должен:

- использовать структурированные данные там, где это возможно;
- поддерживать свободное описание уникальных возможностей предприятия;
- быть пригодным для автоматического анализа;
- поддерживать экспорт в цифровой паспорт предприятия;
- обновляться по мере развития предприятия.

---
```text
EnterpriseProfile
    ├── EnterpriseOKVED ── OKVED
    ├── EnterpriseIndustry ── Industry
    ├── Equipment
    ├── Product ── MaterialItem ── Material
    ├── ProductionFacility
    ├── Warehouse
    ├── LiftingEquipment
    ├── Transport
    ├── EnterpriseCertificate
    └── QualityCapability
```

Схема отражает связи целевой ORM-модели из `08_sqlalchemy_models.md`.
Справочник `TechnologyType` уже существует, но связь технологий с конкретным
профилем в целевой ORM пока не определена. Материал изделия доступен через
`Product → MaterialItem → Material`; отдельная связь профиля со всеми
обрабатываемыми материалами также не определена. Эти два способа хранения
требуют отдельного архитектурного решения и вынесены в backlog.

## 1. Общая информация

Данные цифрового профиля разделяются на три группы:

- регистрационные сведения — юридические реквизиты и официальные `OKVED`;
- рыночная классификация — обслуживаемые предприятием сегменты `Industry` в терминах PNC;
- производственные возможности — продукция, оборудование, технологии, материалы, площадки, качество и инфраструктура.

### 1.1 Регистрационная часть

Регистрационная часть содержит реквизиты предприятия, основной `OKVED` и дополнительные `OKVED`. Связь хранится через `EnterpriseOKVED`; русское наименование берётся из локального классификатора `OKVED`.

Основной `OKVED` означает основной зарегистрированный вид экономической деятельности. Он не подтверждает наличие оборудования, технологий или способность изготовить продукцию.

В целевом онбординге регистрационные сведения могут быть получены по ИНН из
ЕГРЮЛ и предложены пользователю для предварительного заполнения. ЕГРЮЛ —
государственный источник сведений, тогда как `api-fns.ru` — текущий внешний
технический провайдер, а не официальный API ФНС. Провайдерский JSON не входит в
доменную модель: внутренний адаптер нормализует его в согласованный контракт,
после чего пользователь подтверждает данные до сохранения.

Из текущей модели прямыми кандидатами на такое заполнение являются
`company_name`, `inn` и `ogrn`. Заполнение `region_code` требует отдельного
сопоставления адреса с локальным справочником `Region`. Основной и дополнительные
коды сохраняются как `EnterpriseOKVED` только после проверки по локальному
`OKVED`. Текущий HTTP-клиент ещё не содержит нормализованной схемы и сервиса
импорта, поэтому фактический состав доступных полей ответа в коде не закреплён.

### 1.2 Рыночная часть

Рыночная часть содержит связи `EnterpriseIndustry` с одним или несколькими сегментами `Industry`. Признак основной `Industry` означает основной обслуживаемый рынок или рыночную специализацию предприятия в терминах PNC.

Основной `Industry` не является основным `OKVED` и не выводится из него автоматически. Механизм назначения `Industry` предприятию пока не определён.

### 1.3 Производственная часть

Фактическая способность выполнить заказ определяется данными о продукции, оборудовании, технологиях, материалах, производственных площадках, качестве, сертификатах и других подтверждённых возможностях.

Регистрационный импорт не создаёт и не изменяет эти сущности. Он также не
назначает `EnterpriseIndustry`: отраслевая классификация и производственная
анкета остаются самостоятельными шагами формирования профиля.

## Цель производственного профиля

Цель производственного профиля — сформировать цифровую модель производственного предприятия, достаточную для:

- анализа производственных возможностей;
- автоматического подбора заказов;
- формирования рекомендаций по развитию;
- подготовки цифрового паспорта предприятия;
- последующего поиска партнеров и производственной кооперации.
